---
'@adonis-agora/durable': minor
---

Federated console commands are authenticated (found in an internal security audit; the same contract as every Agora lib's console). Until now anything that could publish on `<prefix>-console` could cancel any run, retry it with any input, send signals and updates, complete or fail human tasks, and pause or trigger schedules, under a self-asserted `actor`, and could answer for the app.

**Breaking:**

- The console channel is validated at boot but opened only after it, in the web server or when a `durable:work` loop starts: a one-off ace command no longer subscribes to it (it used to, in every environment).
- A refused message on the command channel (garbage, forged, undecryptable) is logged once per reason (`console commands: refused a command (<reason>)`, uniform reasons) and dropped: it never crashes the app. Token modes show the command key's short id (`sealed to key <id>`) on both sides. Boot errors are `ConsoleAuthConfigError`s with the uniform Agora wording; boot logs end with `; actions on` / `; actions off (…)` and never print a public key.
- An app answers no unauthenticated console command, and `consoleCommands` with no way to authenticate **fails the boot** (web; an ace command only logs it), naming the options. `RedisControlPlane#onConsoleCommand` / `#sendConsoleCommand` and `answerConsoleCommands` refuse to run without authentication.
- **`consoleCommands.actions`** (new, default `false`): every action answers `403` until the app sets `actions: true`. Reads (schedules, worker health, lifecycle links, events) are answered either way.
- **Capabilities on every command:** the console always sends the viewer's capabilities (its `authorize` may now return `capabilities` or `access: 'read'`, kept to durable's console set; otherwise the full set), and the app refuses a command without them (`403`, code `capabilities-required`). Every verb needs its capability, reads included: `durable:read`, `durable:runs:write`, `durable:tasks:write`, `durable:schedules:write`; `durable:console:read` / `durable:console:write` group them (write implies read), and `durable:console:*`, `durable:*` or `*` grant all. One canonical matcher (`console_capabilities.ts`, identical across the Agora libs) checks tokens, viewers and the UI: a `*` anywhere but a literal alias or the last segment of a `durable:` grant (`*:console:*`, `durable:*:write`, `*:read`) grants nothing. In token mode the token's capabilities apply too.
- A console entry with no authentication now **fails the console's boot** unless it says `actions: false` (browse-only), instead of silently degrading to browse-only. The console-side options live on the entry's control plane: `apps.<key>.controlPlane = controlPlanes.redis({ connection, prefix, secret | token + publicKey | crypto, partition })`; `actions` stays on the entry.
- **The viewer's capabilities also apply to the console's own app:** an `authorize` that returns `capabilities` (or `access: 'read'`) refuses the actions the viewer lacks locally too (`403`, "the viewer lacks …"), and the console disables them. Without them, full access as before.
- **Tenant tokens: partition rule.** A classic token must be for this app (`consoleCommands.partition`, by default its crypto partition, else its namespace). On a control plane a console acts on the control plane's own runs by default; acting across tenants (and accepting a tenant app's token, confined to its runs) takes an explicit `consoleCommands.apps` list.
- `console_authorize.ts` is now the Agora-wide contract (identical in every lib): `normalizeConsoleAuthorizeResult` / `ConsoleAuthorizeDecision` (with `status`), `access`, fail-closed `apps`/`tenants`/`capabilities`; `resolveConsoleAuthorize` returns that decision. Durable's previous shape stays available as `normalizeConsoleDecision` / `resolveConsoleGate` / `ConsoleDecision`.

**Zero config with the other Agora libs:**

- **`@adonis-agora/crypto` booted in the app** (detected through its `agora.crypto` binding, never imported): commands are sealed with the key **`console-durable`** (`aes256-gcm`, in the owning app's partition) with no line of config on either side. The Hub (crypto embedded) seals in process for each app's `apps.<key>.controlPlane.partition` (default: its key) and creates the key at boot when missing (never failing it); a console that is a crypto tenant asks the server to seal for the app (`crypto:seal:console-*`). The app opens its own `console-*` keys with its own crypto client and no grant; on a crypto tenant a missing key is one info line (the server provisions it on the console's first seal), a refused or unreachable server a warning. `crypto: false` turns it off; an explicit option is used as given.
- **`@adonis-agora/authkit-client` with calls between apps** (its `authkit.client` binding): the console adds an app-call token for the app to each sealed command and the app verifies it; its audience binds it to the app, and its capabilities cap the command. `token: false` (console) / `verifyTenant: false` (app) turn it off.
- Each side logs its resolved mode(s) once at boot (`console commands: …`, `console commands to "<app>": …`); `agora:doctor` gains `durable.console-commands` (the resolved mode of each side) and the deep `durable.console-commands-key` (the key exists and seals/opens). The APP_KEY-sealed token mode stays available alongside crypto when a verifier and an APP_KEY exist.

**Explicit modes (bring your own):** `crypto` (`{ cipher, key?, owns? }`: `@adonis-agora/crypto` or any KMS, `owns` recognising its ciphertext), authkit/own token (`controlPlane.token` sealed to the app's `publicKey`, derived from its `APP_KEY` and printed by the new `node ace durable:console-key`; `consoleCommands.verifyTenant`, a control plane's own `verifyTenant` by default), or a shared `secret` (HMAC). In every mode an action over a minute old is refused, a replay runs at most once, and a forged answer is ignored. On a `control-plane`, actions are confined to the runs, schedules and worker groups of `consoleCommands.apps` when listed (and of the token's app), including `republishLifecycle({ workflow })` backfills on an app-scoped console.

**Run detail ETag:** the `ETag` of `GET /runs/:id` no longer hashes the run's `input`, `output`, `error` or `searchAttributes` (an unkeyed hash a viewer of redacted runs could test guesses against offline); it covers the run's identity and state, its checkpoint buckets and the summarize threshold.

New exports: `ConsoleCommandAuthOptions`, `ConsoleCryptoOptions`, `consoleCommandPublicKey`, `ConsoleCipher`, `CONSOLE_CRYPTO_KEY`, `ConsoleChannelError`, `UNAUTHORIZED_CONSOLE`, `UNSIGNED_CHANNEL`, `DurableConsoleCommandsConfig`, and from `/dashboard` `DURABLE_CONSOLE_CAPABILITIES`, `DURABLE_CONSOLE_FULL_CAPABILITIES`, `CONSOLE_VERB_CAPABILITY`, `consoleVerbAllowed`, `viewerConsoleCapabilities`, `viewerScopedDashboardEngine`, `FEDERATED_FORBIDDEN`, `CAPABILITIES_REQUIRED`, `AnswerConsoleCommandsOptions`, `normalizeConsoleAuthorizeResult`, `ConsoleAuthorizeDecision`, `ConsoleAccess`, `resolveConsoleGate`; `ConsoleSideOptions`.

**Ace commands exit again (fix, predates this change):** on an `@adonisjs/redis` connection the control plane's subscriber connection (opened by `RedisConnection.subscribe`) was never given back, so `node ace …` commands could hang after finishing. `RedisControlPlane#close()` now unsubscribes its own channels and patterns there and closes the subscriber when nothing else listens on it; and a console/REPL process no longer subscribes to the control plane at all (it still publishes) until it becomes a worker (`durable:work`, via `engine.startConsumers()`).

**authkit key directory:** in token mode an app publishes its command public key to authkit's key directory (`console:durable`, public half only) when its authkit client has one, and a console with a token and no `controlPlane.publicKey` seals to the key it finds there; an explicit `publicKey` still wins.

**Mixed Hubs:** with crypto and authkit's key directory both available, the console picks each app's mode at its first action (token when the app published a key, else crypto; cached 5 minutes, re-decided when the app does not answer). In crypto mode a failing app-call token no longer blocks the action (sent crypto-only, one warning, retried after 5 minutes). `APP_KEY` is read from `config/app.ts`, then `config/encryption.ts`'s default entry, then the environment. The boot error names authkit's `service` as a way in; a crypto tenant checks its key with crypto's `hasKey` when available (no audit noise).
