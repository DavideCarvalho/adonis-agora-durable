Schemas are now [Standard Schema](https://standardschema.dev) based instead of zod-specific, so any library implementing `~standard` works: zod 3.24+ / 4, valibot, arktype, effect schema and others. **`zod` is no longer a runtime dependency** of the package, and neither the emitted JavaScript nor the `.d.ts` files import it. Existing zod 4 schemas keep working with no code changes. The Standard Schema V1 type is vendored (types only) and exported as `StandardSchemaV1`, together with a `validateStandard(schema, value, label)` helper.

- `@Step({ input, output })` and `defineStep` accept any Standard Schema. Sync and async validators both work. The handler receives the input schema's output value (parsed or coerced), and the caller receives the output schema's output value. When the handler is unannotated, `defineStep` infers its types from the schemas: the ref takes the input schema's input type and resolves to the output schema's output type. An annotated handler keeps its own types, as before.
- A value that fails a schema now throws `SchemaValidationError`, a non-retryable `FatalError` with code `schema_validation`. The issues are in `issues` and `details.issues` as `{ message, path: string[] }[]`. Before this change a zod step-schema failure threw a retryable `ZodError`, so a bad payload was retried until `retries` ran out. It now fails on the first attempt.
- New `inputSchema` option on `static workflow`, `engine.register` and `engine.registerRemote`. The input is validated at `start` before a run is created, and the schema's output value becomes the run's input. It runs before the existing `validateInput` function, which is kept and receives the parsed value. An `onEvent` subscriber whose schema rejects a payload is skipped, as with `validateInput`.
- Typed search attributes. Declare `static workflow = { searchAttributes: schema }` (or `searchAttributesSchema` on `engine.register`) and every `ctx.upsertSearchAttributes` validates the merged attributes; a write that doesn't match throws `SchemaValidationError`, and nothing is written or recorded. The schema must validate synchronously. `WorkflowCtx<A>` (and `DynamicWorkflowCtx<A>`) narrows `upsertSearchAttributes` to `Partial<A>`, and the default `WorkflowCtx` behaves as before. `InferSearchAttributes`, `readSearchAttributes(schema, run)` and `attributesOf(WorkflowClass, run)` read attributes back typed. Reads are lenient: history that fails the schema reads as `{}`.
