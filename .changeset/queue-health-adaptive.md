'@adonis-agora/durable': minor
---

The `queue` transport now has worker health, adaptive concurrency and the poison-job bridge, as on `bullmq`.

- Worker health: a queue worker now writes a liveness key for each step name it serves into the worker-key store (refreshed every 10s, expires after 35s). The key carries the worker's `WorkerStatus`: concurrency mode and live limit, in-flight count, RSS, CPU, throughput, p95 and the last adjustment. The transport implements `groupHealth` from these keys, so `engine.workerHealth()`, the dashboard's `/api/workers` and `/api/health` and the Telescope worker panel now report queue groups and render the worker cards. Before, they were empty on this transport. `depth` is the task queue's pending count (`adapter.sizeOf`). It is narrower than BullMQ's depth: the `@adonisjs/queue` adapter contract cannot count jobs in flight or delayed retries. Without a worker-key store (`workerKeys: false`, or no database), nothing can report liveness, so `groupHealth` is not offered. A process with deferred consumers (`node ace` console/REPL) writes no liveness key until it starts consuming.
- `transports.queue({ concurrency: 'adaptive' })`, or `{ mode: 'adaptive', min, max, start, tickMs, ramCeilingPct, cpuCeilingPct }`, uses the same controller as `transports.bullmq({ concurrency })`. Each step name's task loop reads the live limit on every poll and wakes as soon as the limit rises. Before this change the option was not accepted and the transport fell back to a fixed 1. A numeric `concurrency` behaves as before.
- Poison jobs: when the stalled sweep fails a task that stalled more than `maxStalledCount` times, the transport now publishes a retryable failed `StepResult` for that step (`remote step worker failed: stalled more than N times`), like BullMQ's terminal-failure bridge. The engine re-dispatches the step while it has retries left, then fails it into the workflow. Before, the run waited on that step's `pending` checkpoint forever. This works on `@adonisjs/queue` 0.7. On 0.6 the adapter deletes such a job inside its own sweep and reports only a count, so nothing can be published; use `timeoutMs` or `remoteRedispatchMs` there. Stalled result, heartbeat and control jobs are still only failed.
