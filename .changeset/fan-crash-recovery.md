---
'@adonis-agora/durable': minor
---

Runs spread over the engine instances on `bullmq`, `queue` and `db`, and wide `ctx.all` fans survive crashes and scale-downs.

- **Run queue.** A transport can now carry runs as well as steps: `Transport.dispatchRuns(runs, { namespace? })` and `Transport.onDispatchedRun(handler: (run: RunDispatch) => Promise<void>, { concurrency, namespace? })`, with `RunDispatch = { runId, priority?, reason?: 'start' | 'wake', key? }` (`key` names the `pending` state a start is for). Each namespace has its own run queue: an engine dispatches to and consumes its own namespace's (an operator, with no namespace, the transport's own), so a pool's runs stay on that pool's instances. `priority` is the run's: the BullMQ job priority and the `queue` job priority (higher = more urgent); the `db` transport claims oldest first. `bullmq` (`<P>-runs`, `addBulk` in chunks of 500, a start's job id `start-<runId>-<key>`: a start re-sent for the same pending state is queued once, a run that went `pending` again gets a new job even while the previous one is active), `queue` (`<prefix>:runs`, `pushManyOn` when the adapter has it) and `db` (`run` rows of `durable_transport_messages`, claimed under a lease) implement it; `eventEmitter` and `memory` do not. With such a transport and the default dispatcher, the engine consumes the run queue (on driving instances only: not with `drive: false`, not on a control plane) and sends through it every run it would otherwise execute on the instance that triggered it: starts (and so schedules, event triggers, `signalWithStart`, dead-letter and `onError` handlers), `ctx.child` / `ctx.all` child starts, `continue-as-new`, `requeue`, runs put back to `pending` by crash recovery, signal and child-completion wakes, due timers (claimed for `leaseMs` before the hand-off) and freed singleton or queue slots. Runs of one burst go out in batches. The consumer skips a start whose run is no longer `pending` and a wake for a finished run. A failed enqueue leaves a start `pending` for the pending-run poll and resumes a wake locally. `drain()` stops the consumer first and hands back what it takes while draining. New `engine.consumeRuns()` (the engine calls it itself when built; returns the consumer's stop, or `undefined` without a run queue) and `engine.runEnqueued(run)`: the consumer acts on the run's state (runs a `pending` run, resumes a suspended one, skips a finished one).
- **Lost child completions.** Every turn of a `ctx.all` / `ctx.allSettled` parent reads the children it still waits on in batches of 500 through the new optional `StateStore.getRuns(runIds)` (Lucid, in-memory and `CodecStateStore`; `getRun` per child on a store without it) and lists the fan's buffered completions once, instead of two reads per child, and settles the finished ones (failed, cancelled and dead ones as failures: `rejected` entries of `allSettled`). A child settled that way is tagged `durable:child:delivered`, so a notification arriving later is dropped instead of leaving a buffered signal nobody reads. A child's notification to its parent retries store errors with backoff (4 tries) and `drain()` waits for it. A cancelled child (`cancel()`, a compensating cancel) now notifies its parent at once, like a failed or dead one. The state-store contract has a `getRuns` case and `runRunDispatchContract` (on `/testing/conformance`) is new. The Lucid store contract and the `db` transport's run queue are tested on SQLite, Postgres and MySQL.
- **Suspended runs whose step finished.** A wake that finds the run leased by another instance is retried once the lease is free, so a holder that dies mid-turn no longer strands the run until its timer. With `remoteRedispatchMs`, a run waiting on a dispatched `ctx.step` parks no later than `reconcileMs`.
- **Bounded per instance.** An instance executes at most 256 in-process runs and child starts at once (the rest wait as run ids) and takes at most 64 runs from the run queue at once. These bounds are internal; there is no option.

`engine.signal()` on a run-queue transport resolves once the wake is handed to the queue (`status: 'suspended'`) instead of after the resumed turn; use `waitForRun` for the outcome.
