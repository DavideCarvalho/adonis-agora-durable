This page is a flat lookup table of the public API of `@adonis-agora/durable`: the `WorkflowCtx`, `BaseWorkflow` and the decorators, the engine, the `RunGateway`, `defineConfig`, the driver factories, the observability and command building blocks, the errors and the statuses. It is deliberately terse. For the reasoning behind an entry, follow its link to the concept, authoring or reliability page.

Everything below is exported from the package root (`@adonis-agora/durable`) unless a row names a [subpath](#subpath-exports).

## WorkflowCtx

The context handed to a workflow's `run(ctx, input)`. Every interaction with the outside world goes through it so the engine can checkpoint, and the body itself stays deterministic (see [Durability & replay](/docs/durable/concepts/durability)).

### Properties

| Member | Signature | Notes |
| --- | --- | --- |
| `runId` | `readonly runId: string` | This run's id. |

### Steps

| Member | Signature | Notes |
| --- | --- | --- |
| `step` | `step<TInput, TOutput>(handler: StepRef<TInput, TOutput>, input: TInput, opts?: StepDispatchOpts & { compensate?: StepRef<StepUndo<TInput, TOutput>, unknown> \| string }): Promise<TOutput>` | Dispatch a durable step by typed reference (a `@Step` method or a `defineStep` handle). This is the one step primitive, and it is always engine-scheduled: the run suspends until the result lands. `compensate` registers a dispatched [saga undo](/docs/durable/reliability/sagas). | `step` (by name) | `step<TOutput = unknown>(name: string, input: unknown, opts?: StepDispatchOpts & { compensate?: StepRef<StepUndo<unknown, TOutput>, unknown> \| string }): Promise<TOutput>` | The same dispatch addressed by string name, for a cross-runtime handler (e.g. a [Python](/docs/durable/python) step) with no JS reference. |
| `localStep` | `localStep<TOutput>(name: string, fn: (log: StepLogger) => Promise<TOutput>, options?: StepOptions): Promise<TOutput>` | A checkpointed step whose body runs **in the engine process** instead of being dispatched. It can carry an in-memory `compensate` for [sagas](/docs/durable/reliability/sagas). See [Local steps](/docs/durable/concepts/workflows-and-steps#local-in-process-steps). |

### Time

| Member | Signature | Notes |
| --- | --- | --- |
| `sleep` | `sleep(duration: string \| number): Promise<void>` | Durable sleep for a relative duration (`'30s'`, `'2h'`, `'7 days'`, or ms). Uses no compute while waiting and resumes across restarts. See [Sleep & signals](/docs/durable/concepts/sleep-and-signals). |
| `sleepUntil` | `sleepUntil(when: Date \| number): Promise<void>` | Durable sleep until an **absolute** time. The wake time is fixed on the first run, so it is replay-stable. |
| `now` | `now(): Promise<number>` | Deterministic epoch-ms clock: recorded on the first run, the same value on replay. Use it instead of `Date.now()` in a workflow body. See [Versioning & determinism](/docs/durable/authoring/versioning). |

### Supporting option types

| Type | Shape | Notes |
| --- | --- | --- |
| `StepDispatchOpts` | `{ queue?, priority?, fairnessKey?, transport?, retries?, backoff?, backoffMs?, backoffMaxMs?, jitter?, timeoutMs?, pickupTimeoutMs?, requires? }` | Per-call override of the `@Step`-declared policy, merged as `{ ...stepConfigOf(ref), ...opts }`. `queue` routes through a [flow-control](/docs/durable/reliability/flow-control) queue, where `priority` and `fairnessKey` apply. `transport` pins a named transport in the pool. `requires` lists [capabilities](/docs/durable/cluster/handshake#capability-aware-routing) a worker must advertise. See [Dispatch options](/docs/durable/concepts/workflows-and-steps#dispatch-options). |
| `StepOptions` | `{ retries?, backoff?, backoffMs?, backoffMaxMs?, jitter?, timeoutMs?, pickupTimeoutMs?, compensate?, requires? }` | Options for `ctx.localStep` and `ctx.task`. `compensate: () => Promise<void>` registers an in-process saga undo, retried up to `compensationRetries` (default `1`). See [Retries & backoff](/docs/durable/reliability/retries). |
| `BackoffStrategy` | `'fixed' \| 'exp'` | Constant or doubling delay between retries. |
| `StepUndo<TInput, TOutput>` | `{ input: TInput; output: TOutput }` | The single argument a dispatched saga undo receives: the compensated call's own input and result. |
| `UndoOf<H>` | `H extends (input: infer I, ...rest: never[]) => infer R ? StepUndo<I, Awaited<R>> : StepUndo<unknown, unknown>` | Derives an undo's argument from the original step's signature, so a `compensate` ref is compile-checked: `async cancelBooking(undo: UndoOf<FlightService['book']>) { ... }`. |
| `AllOptions` | `{ mode?: 'waitAll' \| 'failFast'; concurrency?: number }` | For `ctx.all` over children. `concurrency` sends waves of `floor(concurrency / 2)`, two at a time. It is part of the fan's identity, so don't change it under an in-flight run. |
| `AllStepsOptions` | `Omit<StepDispatchOpts, 'queue' \| 'timeoutMs' \| 'pickupTimeoutMs'> & { mode?: 'waitAll' \| 'failFast'; concurrency?: number }` | For `ctx.all` over a `@Step`. The retry/backoff options apply to every step of the fan; `concurrency` sends strict waves of that size. |
| `AllSettledOptions` / `AllStepsSettledOptions` | `Omit<AllOptions, 'mode'>` / `Omit<AllStepsOptions, 'mode'>` | The `ctx.allSettled` counterparts. |
| `Settled<T>` | `{ status: 'fulfilled'; value: T } \| { status: 'rejected'; id: string; error: string; code?: string; details?: unknown }` | One item of an `allSettled` fan, in input order. `id` is the child run id or the step id. |
| `ChildCallOptions` | `{ childId?: string; priority?: number }` | Options for `ctx.child` and `ctx.startChild`; a bare string is shorthand for `{ childId }`. `priority` only affects a remote child. |
| `DurableWebhook<TPayload>` | `{ readonly token: string; readonly url?: string; wait(opts?: { timeoutMs?: number }): Promise<TPayload> }` | What `ctx.webhook()` returns. `url` is built by the [`webhookUrl`](#durableconfig) config option. |

### `DynamicWorkflowCtx` — the non-overloaded view

`WorkflowCtx` minus its five overloaded methods, re-declared with one string-addressed signature each: `step(name, input, opts?)`, `child(workflow, input, options?)`, `startChild(workflow, input, options?)`, `all(workflow, inputs, opts?)` and `allSettled(workflow, inputs, opts?)`. Every `WorkflowCtx` is assignable to it without a cast. Depend on it (or a `Pick` of it) in code that drives the ctx by names, such as a graph interpreter, and in test fakes, where satisfying every overload of the full `WorkflowCtx` is impractical:

```ts
type InterpreterCtx = Pick<DynamicWorkflowCtx, 'runId' | 'localStep' | 'child' | 'all' | 'sleep'>
new Interpreter(ctx) // a WorkflowCtx IS a DynamicWorkflowCtx — no `as unknown as` cast
```

### `StepLogger`

The second argument a step handler (and a `ctx.localStep` body) receives. Events it records are checkpointed with the step and rendered under it in the dashboard. See [Steps vs. sub-process events](/docs/durable/concepts/workflows-and-steps#steps-vs-sub-process-events).

| Member | Signature | Notes |
| --- | --- | --- |
| `debug` `info` `warn` `error` | `(message: string, data?: unknown): void` | One method per level. |
| `heartbeat` | `heartbeat(progress?: unknown): void` | Report "alive mid-flight": rearms the step's `timeoutMs` window and persists the latest beat on the checkpoint. Throttled internally (about 5s). See [Reporting liveness](/docs/durable/concepts/workflows-and-steps#reporting-liveness-from-inside-a-long-step). |
| `sub` | `sub(name: string, status: 'ok' \| 'failed' \| 'skipped', message?: string, data?: unknown): void` | Record a sub-step outcome. |
| `subEvent` | `subEvent(e: { id; name; group?; phase?; status?; message?; data? }): void` | Record a sub-process event (a `phase` transition or a terminal `status`). |
| `subProcess` | `subProcess<T>(name: string, body: (sp: SubProcessHandle) => Promise<T> \| T, opts?: { group?: string; id?: string }): Promise<T>` | Time `body` and record `ok` or `failed`. `sp.phase(label)`, `sp.skip(reason)` and `sp.fail(reason)` mark other outcomes. |

#### `currentStep()`

`currentStep(): StepLogger | undefined`, exported from `@adonis-agora/durable`, returns the logger of the step body running on the current async path: the same instance the body received, so what it records lands in the same event list. Every step body has one, local (`ctx.step`, `ctx.localStep`) and remote (a handler on a worker). It is `undefined` outside a step, so a helper deep in your code can instrument itself without being handed the logger and still runs in a unit test:

```ts
import { currentStep } from '@adonis-agora/durable'

export async function insertBatch(rows: Row[]) {
  await db.table('lines').multiInsert(rows)
  currentStep()?.info('inserted batch', { rows: rows.length })
}
```

## Authoring

### `BaseWorkflow`

The base class for a workflow under `app/workflows/`, auto-registered at boot. See [app/workflows](/docs/durable/authoring/app-workflows).

| Member | Signature | Notes |
| --- | --- | --- |
| `workflow` | `static workflow?: WorkflowOptions` | The workflow's identity and options (table below). A class without it is not registrable. |
| `schedule` | `static schedule?: WorkflowScheduleConfig \| WorkflowScheduleConfig[]` | Colocated recurring schedule(s), merged with `config.schedules` (config wins on a `key` collision). See [Scheduling](/docs/durable/authoring/scheduling#colocate-the-schedule-with-the-workflow). |
| `run` | `abstract run(ctx: WorkflowCtx, input: unknown): unknown` | The workflow body. Annotate `input` with the type you want `WorkflowInputOf` to infer. |
| `deadLetter` | `deadLetter?(ctx: WorkflowCtx, dead: DeadLetter): unknown` | Optional inline dead-letter handler, registered as `<name>.dlq` (same version and origin) and started as `dlq:<deadRunId>` when a run of this workflow goes `dead`. `DeadLetter<TInput>` is `{ deadRunId: string; workflow: string; input: TInput; error?: StepError }`. Declaring it with `static workflow.deadLetterWorkflow` throws. See [Dead-letter queue](/docs/durable/reliability/dead-letter#routing-to-a-dlq-workflow). |
| `start` | `static start<C extends WorkflowClass>(this: C, input: WorkflowInputOf<C>, opts?: WorkflowDispatchOptions): Promise<WorkflowOutputOf<C>>` | Run and wait for the result. Outside a workflow: `engine.start` plus `waitForRun(runId, { terminal: true })`. Inside one: `ctx.child`. |
| `dispatch` | `static dispatch<C extends WorkflowClass>(this: C, input: WorkflowInputOf<C>, opts?: WorkflowDispatchOptions): Promise<{ runId: string }>` | Fire-and-forget. Outside a workflow: `engine.start`. Inside one: `ctx.startChild`. |

`WorkflowDispatchOptions` is `{ runId?: string } & StartOptions`. Outside a workflow `runId` sets the new run's id (default `randomUUID()`); inside one it is the deterministic child id, and omitting it lets the ctx derive a replay-stable one. See [Child workflows](/docs/durable/authoring/child-workflows).

### `@Step(nameOrOptions?)` and `defineStep`

`Step(nameOrOptions?: string | StepDecoratorOptions): MethodDecorator` marks a class method as a durable step handler, routed **by name**. Steps under `app/steps/` are discovered and served automatically (config [`stepsPath`](#durableconfig)). See [Workflows & steps](/docs/durable/concepts/workflows-and-steps#2-step-decorator-recommended).

| Form | Notes |
| --- | --- |
| `@Step()` | Name derived as `` `${ClassName}.${method}` ``. |
| `@Step('custom:name')` | Explicit name, a stable cross-runtime contract. |
| `@Step({ name?, input?, output?, retries?, backoff?, backoffMs?, backoffMaxMs?, jitter?, timeoutMs?, pickupTimeoutMs?, requires? })` | `input` / `output` are opt-in [Standard Schemas](/docs/durable/concepts/workflows-and-steps#validation-with-any-standard-schema-library) (zod, valibot, arktype, …) validated at the serve boundary; a failure is a non-retryable `SchemaValidationError`. The rest is the def-level dispatch policy `ctx.step` reads (a per-call `opts` overrides it field by field). See [Retries & backoff](/docs/durable/reliability/retries). |

| `StepDecoratorOptions` field | Type | Notes |
| --- | --- | --- |
| `name` | `string` | Explicit routing name. |
| `input` / `output` | `StandardSchemaV1` | Runtime schemas for the step's input and output — any Standard Schema library. The handler gets the input schema's output value; the caller gets the output schema's output value. |
| `retries` | `number` | Max attempts before the step (and run) fails. |
| `backoff` | `BackoffStrategy` | `'fixed'` or `'exp'`. |
| `backoffMs` / `backoffMaxMs` | `number` | Base delay and upper bound in ms. |
| `jitter` | `boolean` | Random 50–100% jitter on the delay. |
| `timeoutMs` | `number` | Liveness window: no result or heartbeat within it fails the dispatch with `RemoteStepTimeout` (retryable). |
| `pickupTimeoutMs` | `number` | Liveness window before the worker's first heartbeat (queue wait plus pickup). Defaults to `timeoutMs`. See [`pickupTimeoutMs`](/docs/durable/reliability/retries). |
| `requires` | `string[]` | Capabilities a live worker must advertise; with none live, the run parks `blocked`. See [Capability-aware routing](/docs/durable/cluster/handshake#capability-aware-routing). |

| Export | Signature | Notes |
| --- | --- | --- |
| `defineStep` | `defineStep<TInput, TOutput>(name: string, fn: (input: TInput, log: StepLogger) => TOutput \| Promise<TOutput>, config?: Omit<StepDecoratorOptions, 'name'>): StepRef<TInput, TOutput>` | A step handler without a class or decorator. With an `input` / `output` schema and an unannotated handler, the types are inferred: `StepRef<InferInput<input>, InferOutput<output>>`, handler argument `InferOutput<input>`. See [`defineStep`](/docs/durable/concepts/workflows-and-steps#3-definestep). |
| `StepRef<TInput, TOutput>` | `((input: TInput) => Promise<TOutput> \| TOutput) & { [DURABLE_STEP_NAME]?: string; [DURABLE_STEP_CONFIG]?: StepConfig }` | A typed handle onto a stamped step name and policy. |
| `StandardSchemaV1` / `validateStandard` | `validateStandard(schema, value, label): Promise<InferOutput<schema>>` | The vendored [Standard Schema](https://standardschema.dev) V1 type, and the helper every schema slot uses (sync or async `validate`; throws `SchemaValidationError`). |
| `InferSearchAttributes` / `readSearchAttributes` / `attributesOf` | `attributesOf(WorkflowClass, run): A` | Infer a `searchAttributes` schema's shape; read a run's attributes typed through a schema or by workflow class (lenient: history that fails the schema reads as `{}`). |
| `stepNameOf` / `stepConfigOf` | `stepNameOf(ref: unknown): string \| undefined` / `stepConfigOf(ref: unknown): StepConfig \| undefined` | Read the stamped name or policy off a reference. |

### Control-flow signals

`WorkflowSuspended` and `ContinueAsNew` are thrown **internally** to unwind the current turn (a durable sleep, a still-pending step, `ctx.continueAsNew`). They are not failures. Because they use the same exception mechanism as a real step failure, a workflow's own `try`/`catch` around `ctx.step`, `ctx.sleep` and so on can catch one, and it must rethrow it untouched before running any cleanup. Otherwise the cleanup is recorded as extra history during what replay later sees as a plain suspend, and the run fails with `NonDeterminismError` on resume. See [Catching errors](/docs/durable/concepts/workflows-and-steps#catching-errors--rethrow-control-flow-signals) and [Sagas](/docs/durable/reliability/sagas).

| Export | Signature | Notes |
| --- | --- | --- |
| `CONTROL_FLOW_SIGNAL` | `const CONTROL_FLOW_SIGNAL: unique symbol` | `Symbol.for('@agora/durable:control-flow')`, the global-registry marker stamped on every control-flow signal class. Rarely used directly. |
| `isWorkflowControlFlowSignal` | `isWorkflowControlFlowSignal(error: unknown): boolean` | `true` for `WorkflowSuspended` and `ContinueAsNew`, whichever module copy threw them. Not true for a cancellation or a `FatalError` / step rejection, which are real outcomes a `catch` may handle. |

```ts
try {
  await ctx.step(chargeCard, input)
} catch (error) {
  if (isWorkflowControlFlowSignal(error)) throw error // suspend / continue-as-new: rethrow as-is
  await ctx.step(refund, input) // a real failure: safe to compensate
  throw error
}
```

## Statuses

### Run status (`RunStatus`)

| Status | Meaning |
| --- | --- |
| `pending` | Created and enqueued by `start`, not yet picked up. |
| `running` | A worker is executing (or replaying) the body. |
| `suspended` | Parked with zero compute on a sleep, a signal, event or update, an awaited step or a child. |
| `blocked` | Parked because no live worker can run the next dispatch (a required capability is unadvertised, or every live worker is protocol-incompatible). Not terminal: the blocked-recovery poll re-drives it once a capable worker appears. See [Handshake](/docs/durable/cluster/handshake). |
| `completed` | Finished successfully. Terminal. |
| `failed` | Finished with an unrecovered error. Terminal. |
| `cancelled` | Cancelled, with or without compensation, or past its `executionTimeout`. Terminal. |
| `dead` | Dead-lettered: crash recovery gave up after `maxRecoveryAttempts`. Terminal. |

Only `completed`, `failed`, `cancelled` and `dead` are terminal (`TerminalRunStatus`, listed in `TERMINAL_RUN_STATUSES`). Only those are eligible for [retention pruning](/docs/durable/reliability/retention), and they never transition on their own again.

### Checkpoint status (`StepCheckpoint['status']`)

| Status | Meaning |
| --- | --- |
| `pending` | A remote step was dispatched and awaits its worker's result; the run is durably suspended. |
| `running` | A local step's body is executing in-process right now (see [`trackStepStart`](#durableconfig)). |
| `completed` | Settled successfully. Short-circuits on replay: the step is not re-executed. |
| `failed` | Settled with an error. Re-awaited (remote) or re-run (local) on replay unless retries are exhausted. |
