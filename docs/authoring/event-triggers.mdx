A scheduled workflow starts on time; an **event-triggered workflow** starts when something happens — a payment succeeded, a webhook arrived, a document changed. Instead of you wiring "event → `engine.start(...)`" by hand, the workflow class declares its triggers and the durable provider bridges the event source into the engine for you.

This page is about the **source**. The engine side (`publishEvent`, `onEvent`, `ctx.waitForEvent`, coalescing and buffering) is covered in the [Events guide](/docs/durable/authoring/events). The source is the **AdonisJS emitter**, with exact event names.

To start a workflow from a `@adonis-agora/diagnostics` event, write a diagnostics listener that dispatches it. See [Starting a workflow from an event](/docs/durable/authoring/diagnostics-listeners#starting-a-workflow-from-an-event).

## Authoring — decorators and `static on`

```ts
import { BaseWorkflow, OnEvent, type WorkflowCtx } from '@adonis-agora/durable'

@OnEvent({ event: 'order:placed' })
export class ProcessOrderWorkflow extends BaseWorkflow {
  static workflow = { name: 'process-order' }
  async run(ctx: WorkflowCtx, input: { orderId: string }) {
    // input is the event payload
  }
}
```

Both forms are supported, exactly like schedules:

- `@OnEvent({ event })`, a named-parameter decorator, and
- a colocated `static on` literal, one trigger or an array (the decorator only stamps `static on`):

```ts
static on = [
  { source: 'emitter', event: 'order:placed' },
  { source: 'emitter', event: 'order:paid' },
]
```

Repeated decorators and an existing `static on` accumulate (decorators prepend, top-first). A `static on` entry with any other `source` fails the app's boot.

<Callout type="info" title="Exact names only">
The Adonis emitter has no wildcard, so `@OnEvent` matches **exact names only**.
</Callout>

## How it fires

Each trigger routes through [`engine.publishEvent(event, payload)`](/docs/durable/authoring/events#publishing-an-event), which starts a fresh run of every workflow registered with that `onEvent` name, with the payload as input. The same publish also resumes any run parked on `ctx.waitForEvent(event)`. The bridge passes no `opts.id`, so every emitted event starts its subscribers once. To dedupe an upstream's redeliveries, call `publishEvent` yourself with the upstream's id (see [Idempotent publishing](/docs/durable/authoring/events#idempotent-publishing--optsid)).

The run input still goes through the workflow's [`inputSchema`](/docs/durable/authoring/app-workflows#validating-the-input), so a payload it rejects starts nothing.

## Wiring

No config needed. The provider reads the triggers from discovered workflow classes (`static on`) and bridges the app's emitter at boot. If the emitter is unavailable, the triggers are inert.

A few consequences of how the bridge is wired:

- **It is in-process.** The emitter is local to one Node process, so an event starts runs only in the process that emitted it. A fact emitted on a web replica is published by that replica; workers don't see it. To fan a fact out across processes, call [`engine.publishEvent`](/docs/durable/authoring/events#publishing-an-event) from a shared transport consumer instead, or emit it on the diagnostics bus and handle it with a [durable diagnostics listener](/docs/durable/authoring/diagnostics-listeners).
- **It needs an engine.** The bridge is attached by the provider's `boot` on the roles that own one (`standalone` and `control-plane`). A store-less `tenant` pod attaches no bridge, and neither does a warmed-up command (`node ace codegen` and similar) that never starts the app.

### Triggering from your own app events

`@OnEvent` works with any event on the app emitter, not only library events. Declare the event in `EventsList` so `emitter.emit` type-checks:

```ts title="app/workflows/send_welcome_workflow.ts"
import { BaseWorkflow, OnEvent, type WorkflowCtx } from '@adonis-agora/durable'

declare module '@adonisjs/core/types' {
  interface EventsList {
    'user:registered': { email: string }
  }
}

@OnEvent({ event: 'user:registered' })
export default class SendWelcomeWorkflow extends BaseWorkflow {
  static workflow = { name: 'send-welcome' }

  async run(ctx: WorkflowCtx, input: { email: string }) {
    await ctx.step('mail.send-welcome', input)
  }
}
```

```ts
import emitter from '@adonisjs/core/services/emitter'

await emitter.emit('user:registered', { email: user.email }) // starts one send-welcome run
```
